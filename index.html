HOW IT WORKS

不是又一个待办工具，
而是一条完整的个人开发工作流。

星枢优先读取已经存在的本地证据，再把信息组织成可执行状态。自动化可以帮你整理和推进，但最终决定始终留给你。

01
⌁

采集真实证据

只读扫描 Codex 会话、Git 提交、项目目录、测试和发布记录，不依靠回忆虚构进度。

Codex · Git · 测试 · 工时
02
◎

统一项目身份

把改名或迁移后的目录、Codex 对话、Git 仓库与 TAPD 项目映射成同一个规范项目。

目录 · 别名 · 映射 · 证据链
03
▷

从状态直接行动

启动项目、处理缺陷、运行测试、查看 Git 差异或触发 Jenkins 发布，都从当前工作现场继续。

运行 · 测试 · 发布 · 自动队列
04
✓

人工确认与复用

确认 · 报告 · 知识 · 复盘
CAPABILITIES

覆盖日常开发，而不是堆满孤立功能。

功能按实际使用场景归组。每个模块都围绕“看清状态、继续工作、留下证据”设计。

  • 炫酷统一加载状态

  • 只分析已暂存文件

LOCAL FIRST & HUMAN CONTROL

自动化可以积极，
权限边界必须保守。

工作台不要求部署服务端。工作记录、项目映射、报告和知识默认保存在 Windows 本机；令牌和密码交给 Windows 凭据管理器保存。

01原始数据留在本机SQLite 本地存储，Codex 与 Git 扫描默认只读。
02秘密信息不进入数据库TAPD、Git、邮箱和 API 凭据使用系统凭据库。
03危险操作由人决定提交、推送、缺陷回写和真实测试不会静默执行。
04升级前保护本地数据自动备份并只保留最近 10 条内部可用备份。
